Este bloque introduce los conceptos básicos de Docker. Es fundamental que los estudiantes entiendan la diferencia entre imágenes y contenedores.

¿Qué es Docker?

Plataforma de contenedores

Empaqueta aplicaciones y dependencias

Contenedores ligeros y portables

Docker permite empaquetar aplicaciones de forma que funcionen igual en cualquier entorno.

Contenedores vs Máquinas Virtuales

Máquinas Virtuales

  • Sistema operativo completo
  • Hipervisor necesario
  • Mayor consumo de recursos
  • Inicio más lento

Contenedores Docker

  • Comparte kernel del host
  • Sin hipervisor
  • Menor consumo de recursos
  • Inicio rápido
La diferencia clave es que los contenedores comparten el kernel del host, mientras que las VMs necesitan un sistema operativo completo.

Conceptos Fundamentales

  • Imagen: Plantilla de solo lectura
  • Contenedor: Instancia ejecutable de una imagen
  • Dockerfile: Instrucciones para construir imágenes
  • Registro: Repositorio de imágenes (Docker Hub, GCR, etc.)
Es crucial que entiendan que las imágenes son inmutables y los contenedores son instancias efímeras.

Arquitectura de Docker

  • Cliente Docker: Interfaz de línea de comandos
  • Daemon Docker: Gestiona contenedores, imágenes, volúmenes
  • containerd: Gestiona el ciclo de vida de contenedores
  • Kernel del host: Proporciona aislamiento
Docker utiliza una arquitectura cliente-servidor. El daemon es el componente principal que gestiona todo.

Comandos Básicos: Imágenes


# Formato nuevo (recomendado)
docker image ls          # Listar imágenes
docker image pull <img>  # Descargar imagen
docker image rm <img>    # Eliminar imagen
docker image prune       # Limpiar imágenes no usadas
docker image inspect <img> # Inspeccionar imagen

Formato antiguo: docker images (aún válido)

Enfatizar el uso del formato nuevo que es más explícito y claro.

Comandos Básicos: Contenedores


# Formato nuevo (recomendado)
docker container ls      # Listar contenedores activos
docker container ls -a   # Listar todos los contenedores
docker container stop <cont>   # Detener contenedor
docker container start <cont>  # Iniciar contenedor
docker container rm <cont>     # Eliminar contenedor
docker container exec -it <cont> <cmd> # Ejecutar comando
Mostrar la diferencia entre contenedores en ejecución y detenidos.

Volúmenes en Docker

Permiten persistencia de datos

Comparten archivos entre host y contenedor

Tipos:

  • Named Volumes: Gestionados por Docker
  • Bind Mounts: Mapean directorios del host
  • tmpfs Mounts: En memoria RAM
Sin volúmenes, todos los datos se pierden al eliminar el contenedor.

Comandos de Volúmenes


docker volume create <nombre>    # Crear volumen
docker volume ls                  # Listar volúmenes
docker volume inspect <nombre>   # Inspeccionar volumen
docker volume rm <nombre>        # Eliminar volumen
docker volume prune               # Limpiar volúmenes no usados
Los volúmenes nombrados son ideales para producción, los bind mounts para desarrollo.

Publicación de Puertos

Los contenedores están aislados por defecto

Necesitamos publicar puertos para acceder desde el host


# Mapeo específico
docker run -p 8080:80 nginx:alpine

# Puerto aleatorio
docker run -p 80 nginx:alpine

# Publicar todos los EXPOSE
docker run -P nginx:alpine
IMPORTANTE: EXPOSE en Dockerfile solo documenta, no publica. Se necesita -p para publicar realmente.

EXPOSE vs -p

EXPOSE en Dockerfile

  • Solo documentación
  • No publica puertos
  • Información para otros desarrolladores

-p en docker run

  • Publicación real
  • Mapea host:contenedor
  • Necesario para acceso externo
Esta es una confusión común. Aclarar que EXPOSE es solo documentación.

¿Qué es un Dockerfile?

Archivo de texto con instrucciones

Define cómo construir una imagen

Cada instrucción crea una capa

Docker cachea capas para builds rápidos

El orden de las instrucciones es crucial para aprovechar el cache.

Sintaxis Básica de Dockerfile


FROM python:3.11-slim    # Imagen base (obligatoria)
WORKDIR /app             # Directorio de trabajo
COPY requirements.txt .  # Copiar archivos
RUN pip install -r requirements.txt  # Ejecutar comandos
COPY app.py .            # Copiar código
EXPOSE 5000              # Documentar puerto
CMD ["python", "app.py"] # Comando por defecto
Explicar cada instrucción y su propósito. FROM debe ser la primera.

Mejores Prácticas

  • Usar imágenes base oficiales y específicas
  • Evitar latest para reproducibilidad
  • Minimizar número de capas
  • Ordenar instrucciones de estáticas a dinámicas
  • Usar .dockerignore
  • Nunca incluir secretos en imágenes
Estas prácticas mejoran seguridad, tamaño y velocidad de build.

Optimización del Cache


# ❌ MAL: Dependencias se reinstalan siempre
COPY . .
RUN pip install -r requirements.txt

# ✅ BIEN: Cache de dependencias
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY app.py .

Las capas se cachean si no cambian

Este es uno de los errores más comunes. Mostrar cómo el orden afecta el cache.

Multi-stage Builds

Múltiples imágenes FROM en un Dockerfile

Copiar artefactos entre etapas

Reduce tamaño final de la imagen


FROM python:3.11-slim as builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user -r requirements.txt

FROM python:3.11-slim
COPY --from=builder /root/.local /root/.local
COPY app.py .
CMD ["python", "app.py"]
Útil para aplicaciones que necesitan herramientas de build pesadas pero solo requieren el resultado final.

Ejemplo: Servidor Web Nginx


FROM nginx:1.25-alpine
WORKDIR /usr/share/nginx/html
COPY index.html /usr/share/nginx/html/
COPY assets/ /usr/share/nginx/html/assets/
EXPOSE 80

Contenido embebido en la imagen

Portable y versionado

Comparar con bind mounts de la Práctica 1. Este enfoque es mejor para producción.

¿Qué son DevContainers?

Especificación para entornos de desarrollo

Define entorno completo en contenedor

Garantiza consistencia entre desarrolladores

Elimina problemas de "funciona en mi máquina"

DevContainers es una especificación abierta, no solo de Docker.

Ventajas de DevContainers

  • Consistencia entre desarrolladores
  • Fácil onboarding de nuevos miembros
  • Aislamiento de dependencias del host
  • Reproducibilidad exacta del entorno
  • Mismo entorno en desarrollo y CI/CD
Especialmente útil cuando diferentes desarrolladores usan diferentes sistemas operativos.

Configuración Básica

Archivo: .devcontainer/devcontainer.json


{
  "name": "Python Development",
  "image": "python:3.11-slim",
  "customizations": {
    "vscode": {
      "extensions": [
        "ms-python.python",
        "ms-python.vscode-pylance"
      ]
    }
  },
  "postCreateCommand": "pip install -r requirements.txt"
}
Mostrar cómo se configura el entorno completo con extensiones y comandos.

Casos de Uso

  • Proyectos con dependencias específicas del sistema
  • Equipos con diferentes sistemas operativos
  • Necesidad de versiones específicas de herramientas
  • Desarrollo que requiere servicios adicionales (BD, colas)
  • Proyectos legacy con dependencias complejas
No todos los proyectos necesitan DevContainers, pero son muy útiles en estos casos.

¿Qué es Docker Compose?

Herramienta para aplicaciones multi-contenedor

Define servicios en archivo YAML

Gestiona dependencias, redes y volúmenes

Un solo comando para levantar toda la aplicación

Docker Compose simplifica enormemente la gestión de múltiples contenedores relacionados.

Conceptos Fundamentales

  • Servicio: Contenedor definido en docker-compose.yml
  • Volumen: Persistencia de datos
  • Red: Comunicación entre contenedores
  • Dependencias: Orden de inicio de servicios
Cada servicio puede tener su propia configuración de imagen, variables de entorno, volúmenes, etc.

Estructura de docker-compose.yml


version: '3.8'

services:
  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data

  app:
    build: .
    env_file: .env
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "5000:5000"

volumes:
  postgres_data:
Mostrar la estructura básica. Explicar cada sección.

¿Qué es un ORM?

ORM (Object-Relational Mapping): Técnica que mapea objetos de programación a tablas de base de datos relacionales

Ventajas:

  • Código más legible y mantenible
  • Protección contra inyección SQL
  • Independencia del motor de base de datos
  • Validación automática de datos
Explicar que un ORM permite trabajar con bases de datos usando objetos Python en lugar de escribir SQL directo. Esto hace el código más seguro y mantenible.

ORM: Concepto Visual

Sin ORM (SQL directo)


cursor.execute("""
    SELECT id, title, 
           completed 
    FROM tasks 
    WHERE id = %s
""", (task_id,))

Con ORM (SQLAlchemy)


task = Task.query.get(task_id)
task.completed = True
db.session.commit()

El ORM traduce automáticamente objetos Python a SQL

Mostrar la diferencia entre escribir SQL directo y usar un ORM. El código con ORM es más legible y seguro.

SQLAlchemy

SQLAlchemy: ORM más popular para Python

Componentes principales:

  • Modelo: Clase Python que representa una tabla
  • Sesión: Contexto de trabajo con la base de datos
  • Query: Objeto para consultar datos usando métodos Python

Flask-SQLAlchemy: Extensión que simplifica la integración con Flask

SQLAlchemy es el estándar de facto para trabajar con bases de datos en Python. Flask-SQLAlchemy añade integración específica con Flask.

Ejemplo de Modelo SQLAlchemy


from app import db
from datetime import datetime

class Task(db.Model):
    __tablename__ = 'tasks'
    
    id = db.Column(db.Integer, primary_key=True)
    title = db.Column(db.String(200), nullable=False)
    description = db.Column(db.Text, nullable=True)
    completed = db.Column(db.Boolean, default=False)
    created_at = db.Column(db.DateTime, default=datetime.utcnow)
    
    def to_dict(self):
        return {
            'id': self.id,
            'title': self.title,
            'completed': self.completed
        }

Cada atributo representa una columna en la tabla

Mostrar cómo se define un modelo. Cada columna se define como un atributo de clase con su tipo y restricciones.

Flujo de Datos Completo

  1. Cliente envía request HTTP (POST /tasks)
  2. Flask recibe request en ruta definida
  3. Ruta valida datos y crea instancia del modelo
  4. SQLAlchemy traduce objeto Python a SQL INSERT
  5. PostgreSQL ejecuta query y almacena datos
  6. SQLAlchemy convierte resultado a objeto Python
  7. Flask serializa objeto a JSON y responde

Todo esto ocurre de forma transparente gracias al ORM
