¿Qué es PaaS?

Platform as a Service (PaaS)

Abstrae infraestructura completa

Desarrolladores se enfocan en código

Responsabilidad Compartida

  • Infraestructura física

  • Herramientas de desarrollo

Desarrollador gestiona:

  • Código de aplicación
  • Configuración de app
  • Datos de aplicación
  • Seguridad a nivel app

Arquitectura Serverless

  • Código se ejecuta en contenedores efímeros
  • Escalado automático desde cero

Lifecycle de una Función

  1. Cold Start: Inicialización del contenedor
  2. Warm: Reutilización de contenedor existente
  3. Invocación: Ejecución del código
  4. Timeout: Destrucción después de inactividad

Tipos de Triggers

  • HTTP: Invocación mediante peticiones HTTP
  • Cloud Storage: Eventos de almacenamiento
  • Pub/Sub: Mensajes de Pub/Sub
  • Firestore: Cambios en base de datos
  • Eventarc: Eventos de múltiples servicios

HTTP vs Event Triggers

HTTP Triggers

  • @functions_framework.http
  • Recibe flask.Request
  • APIs REST, webhooks
  • Respuesta síncrona

Event Triggers

  • @functions_framework.cloud_event
  • Formato CloudEvents
  • Storage, Pub/Sub, etc.
  • Procesamiento asíncrono

CloudEvents: Formato Estándar

CloudEvents es un estándar de la industria para representar eventos de manera consistente

Proporciona estructura unificada independientemente de la fuente

Estructura de CloudEvents

Un evento CloudEvent contiene campos estándar:

  • id: Identificador único del evento
  • type: Tipo de evento (ej: google.cloud.storage.object.v1.finalized)
  • source: Origen del evento (servicio que generó el evento)
  • time: Timestamp de cuando ocurrió el evento
  • data: Datos específicos del evento (varía según el tipo)

Ejemplo: Evento Cloud Storage


{
  "id": "event-123",
  "type": "google.cloud.storage.object.v1.finalized",
  "source": "//storage.googleapis.com/buckets/mi-bucket",
  "time": "2024-11-01T12:00:00Z",
  "data": {
    "bucket": "mi-bucket",
    "name": "archivo.csv",
    "contentType": "text/csv",
    "size": "1024"
  }
}

Acceso a Datos en Python

En funciones con @functions_framework.cloud_event:


@functions_framework.cloud_event
def process_event(cloud_event):
    # Metadata del evento
    event_id = cloud_event.get('id')
    event_type = cloud_event.get('type')
    
    # Datos específicos del evento
    event_data = cloud_event.get('data', {})
    bucket = event_data.get('bucket')
    file_name = event_data.get('name')

Google Cloud Pub/Sub

Mensajería asíncrona distribuida

Desacopla componentes mediante eventos

Conceptos Fundamentales

  • Topics: Canales donde se publican mensajes
  • Messages: Unidades de datos con payload y atributos
  • Subscriptions: Puntos de consumo desde topics
  • Publishers: Componentes que envían mensajes
  • Subscribers: Componentes que consumen mensajes

Flujo de Mensajes


[Publisher] → [Topic] → [Subscription] → [Subscriber]

Múltiples subscriptions pueden consumir del mismo topic

Pull vs Push Subscriptions

Pull

  • Cliente solicita mensajes
  • Control sobre tasa de consumo
  • Ideal para procesamiento batch

Push

  • Entrega automática a endpoint
  • Menor latencia
  • Ideal para Cloud Run Functions

Delivery Semantics

  • At-least-once: Garantiza al menos una entrega
  • Exactly-once: Garantiza exactamente una entrega (opcional)
  • Aplicaciones deben ser idempotentes
  • Mensajes deben confirmarse (ack)

Integración con Cloud Run Functions

  • Functions pueden tener trigger Pub/Sub
  • Subscription se crea automáticamente
  • Mensajes llegan como CloudEvents
  • Escalado automático según volumen
  • Formato estándar CloudEvents
